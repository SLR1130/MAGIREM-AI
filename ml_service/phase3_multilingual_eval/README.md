Status: **candidate stimuli prepared; independent annotation and model scoring have not happened.** This folder is separate from training data and production artifacts. Nothing here is a production change.

- `reviewer_a_blind.csv` and `reviewer_b_blind.csv` — blank, independently distributed forms generated by `phase3_multilingual_eval.py prepare`. They do not contain intended labels or scenario-family IDs.

- `manifest.json` — frozen candidate-bank hash and structural audit summary, generated by `prepare`.
- `blind_case_id_map.json` — private random mapping from opaque reviewer IDs to internal family/language groups. It is ignored by Git and must never be distributed to reviewers.

- `reviewed_dataset_manifest.json` and `.sha256` — created only after genuine completed annotations pass validation; neither exists until human review is supplied.

## Dataset scope and provenance

There are 48 original fictional scenario families and four language renderings per family (192 candidate utterances total): English, standardized Filipino, colloquial Tagalog, and Taglish. Each family is one source group. All four language variants remain together in a **final-holdout-only** evaluation set; none is assigned to training or threshold calibration. The family-level correspondence is intentional and must not be split across any future training/evaluation partition. Reviewer forms use random opaque per-utterance IDs backed by a private mapping file, so IDs do not reveal the family or language suffix. Distribute only the reviewer form, not `candidate_bank.jsonl`, `blind_case_id_map.json`, or the generation script.

All stimuli were newly authored for this package on 2026-11-09. No identifiable student messages, conversations, database rows, or external corpus records were used. `provisional_label` is the author's intended class, **not verified ground truth**. The existing training corpus has incomplete source provenance, so lexical overlap with that corpus has not been certified in this preparation step. Before scoring, run `overlap` only against an institutionally/owner-approved de-identified training export. The command refuses obvious email/phone/URL patterns and writes only hashes and opaque row indexes, never source text. That heuristic is not a substitute for a privacy review.

The language distinction is operational, not a claim that Filipino and Tagalog are separate languages in a strict linguistic sense: `FILIPINO` uses more standardized/formal Filipino phrasing; `TAGALOG` uses conversational colloquial Tagalog; `TAGLISH` uses natural clause-level code-switching; `ENGLISH` is English. A language-proficient reviewer may correct the language tag and document the correction.

## Six-class annotation guide

Assign one primary class only when the text supports it. Do not infer a diagnosis, intensity, or a related emotion that is merely plausible.

- `joy`: expressed positive affect, pleasure, happiness, delight, or celebration. Confidence/pride alone is not a separate class; if pride is the only signal, mark the case unclear rather than force joy.
- `sadness`: low mood, disappointment, discouragement, loneliness, or hurt without bereavement being the defining context.
- `anxiety`: worry, nervousness, apprehension, fear, or tension about a possible/current threat or uncertain outcome. This taxonomy has no separate fear class.
- `anger`: irritation, frustration, resentment, or anger directed at an event/person/boundary violation.
- `grief`: sadness specifically centered on a death or bereavement. Ordinary disappointment, separation, or missing someone is not automatically grief.
- `neutral`: factual/logistical content with no clearly expressed emotion. Neutral is not a synonym for calm, emotionally suppressed, or “the model was unsure.”

Use status `mixed` when two or more classes are genuinely supported but no primary class dominates; if one class is clearly primary, use `clear` with that class and add the `mixed_emotion` issue tag. Use `uncertain` when an emotional signal exists but its class is not safely identifiable; `unclear` when meaning/attribution is ambiguous; `attributed_other` when only another person's feeling is reported; and `out_of_scope` for unusable/unsafe material. A clearly interpretable factual or non-affective message is the `neutral` class, not a separate `no_emotion` status. For all non-`clear` statuses leave the six-class label blank and explain the decision. Never convert uncertainty into `neutral`. Optional semicolon-separated issue tags identify unclear language, mixed emotion, third-person attribution, sarcasm, slang, Filipino/Taglish interpretation differences, or other issues.

## Independent annotation protocol

1. A coordinator verifies two distinct real human reviewers privately, then distributes the blind CSVs separately. Reviewers must not see the provisional key, model output, or one another's answers before submitting. The tool checks distinct pseudonymous IDs and per-row independence attestations; it cannot itself prove a person's identity or independence, so the coordinator retains that responsibility outside this dataset.
2. Each reviewer must be proficient in every language style they annotate and complete the per-row proficiency and independent-review attestations, `status`, `label` (only for `clear`), a 1–3 certainty score, optional issue tags, and a rationale for all non-clear/ambiguous cases. Keep the identity roster separately under the approved process.
3. Run `merge-reviews` to preserve both original forms and create a separate adjudication worksheet. The worksheet flags disagreements and shows both rationales; it contains no provisional labels. A third qualified adjudicator reviews every case, confirms language proficiency, attests they have not seen the model output or provisional key, and records a final status/label. Give a reason for disagreements, changes, language corrections, and every non-clear decision.
4. Run the privacy-approved overlap check, then `freeze-reviews`. It validates all 192 IDs, both completed independent reviews, every adjudication row, label/status compatibility, distinct reviewers/adjudicator, attestation fields, and the clear overlap report. It creates a reviewed manifest plus SHA-256 sidecar bound to the exact candidate bank, review files, adjudication, and overlap report. The scorer requires that frozen manifest and refuses changed inputs.
5. Do not tune the model, thresholds, prompts, or preprocessing on these cases. If a stimulus changes after review, issue a new dataset version and repeat review for affected cases. Report scorable coverage, unresolved/mixed/attributed counts, inter-rater agreement, per-class and per-language support, confusion, precision/recall/F1, confidence calibration, and performance by length/expression type. Never fold unresolved rows into the six-class score. The scorer reports case-level Wilson intervals and a deterministic scenario-family cluster-bootstrap accuracy interval, keeping the four related language renderings together during resampling.

The initial 8 examples per class/language cell are suitable for a reviewed diagnostic pilot, not a high-precision accuracy claim. With only 8 cases in a cell, uncertainty intervals will be wide. The four language renditions within each scenario are related observations, not four independent scenarios. If reviewer corrections or exclusions make a cell smaller, disclose that denominator; do not backfill with more AI-generated “ground truth” without a new, independently reviewed version.

## Commands

From the repository root, using the project's Python environment:

```powershell
.venv\Scripts\python.exe ml_service\phase3_multilingual_eval\phase3_multilingual_eval.py audit
.venv\Scripts\python.exe ml_service\phase3_multilingual_eval\phase3_multilingual_eval.py prepare
```

`prepare` will refuse to overwrite any form that contains responses. After both genuine reviewers complete their separate files, create (but do not auto-accept) the adjudication worksheet. The merge validates the exact frozen text and language and shows both decisions/rationales without exposing provisional labels:

```powershell
.venv\Scripts\python.exe ml_service\phase3_multilingual_eval\phase3_multilingual_eval.py merge-reviews --reviewer-a <completed-a.csv> --reviewer-b <completed-b.csv> --output ml_service\phase3_multilingual_eval\adjudication_working.csv
```

After the owner/privacy steward supplies a de-identified export with `text` and `split` fields and confirms it is permitted for overlap checking:

```powershell
.venv\Scripts\python.exe ml_service\phase3_multilingual_eval\phase3_multilingual_eval.py overlap --training-corpus <approved-deidentified-training.jsonl> --deidentified-confirmed --output ml_service\phase3_multilingual_eval\overlap_audit.json
```

The overlap command also requires `--deidentified-confirmed`; add this flag only after the owner/privacy steward has approved and checked the export. It reports exact/near-match counts with opaque candidate IDs and training row numbers, never raw text. It only checks obvious email, URL, and phone patterns—not names or every privacy risk—and must not be used on any identifiable student data.

After adjudication and a clear overlap report, freeze the reviewed package (this step will fail until all real annotations exist):

```powershell
.venv\Scripts\python.exe ml_service\phase3_multilingual_eval\phase3_multilingual_eval.py freeze-reviews --reviewer-a <completed-a.csv> --reviewer-b <completed-b.csv> --adjudication ml_service\phase3_multilingual_eval\adjudication_working.csv --overlap-report ml_service\phase3_multilingual_eval\overlap_audit.json
```

Only after a reviewed manifest and SHA-256 sidecar exist:

```powershell
.venv\Scripts\python.exe ml_service\phase3_multilingual_eval\phase3_multilingual_eval.py score --reviewer-a <completed-a.csv> --reviewer-b <completed-b.csv> --adjudication ml_service\phase3_multilingual_eval\adjudication_working.csv --overlap-report ml_service\phase3_multilingual_eval\overlap_audit.json --reviewed-manifest ml_service\phase3_multilingual_eval\reviewed_dataset_manifest.json --output ml_service\phase3_multilingual_eval\phase3_production_baseline.json
```

`score` is read-only with respect to source data/checkpoints and refuses missing/changed manifests, missing or duplicate IDs, blank annotations, invalid labels, unverified reviewer/adjudicator attestations, incomplete adjudication, or a non-clear overlap report. It loads the existing production classifier only; it does not train or save checkpoints. **Do not run `score` until the human-review gate is genuinely complete.**
